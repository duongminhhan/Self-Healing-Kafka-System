# Chatbot validation

## Grounded pipeline

Every `POST /api/v1/chat` request follows one path:

1. The application sends the original question as a parameter to
   `dbo.spSearchConnectorHealingLogs`.
2. SQL Server ranks matching rows from the existing `ConnectorHealingLogs` table
   by connector name, event type, message, and JSON details, returning at most
   `OLLAMA_CONTEXT_LOG_LIMIT` rows.
3. The application redacts sensitive JSON keys, then sends the original question
   and those exact rows to Ollama.
4. Ollama generates the Vietnamese response. The prompt forbids operational facts
   outside the supplied rows and requires cited log IDs. The response's `sources`
   field returns the same redacted evidence for verification.

There is no question-specific routing, no open SQL generated by the model, and
no write action available to the chat endpoint.

## One-time local setup

1. Start SQL Server and Ollama, and ensure the selected Ollama model is installed:

   ```powershell
   docker start poc-mssql poc-ollama
   docker exec poc-ollama ollama list
   ```

2. Apply the existing table scripts and all runtime procedures, including:

   ```text
   sql/ingest_reference/stored-procedures/spSearchConnectorHealingLogs.sql
   ```

   This procedure uses the existing log table only; it creates no table, index,
   or schema.

3. Configure the selected `env/<environment>.env`:

   ```dotenv
   CHAT_API_ENABLED=true
   CHAT_API_PATH_PREFIX=/api/v1
   OLLAMA_ENABLED=true
   OLLAMA_BASE_URL=http://127.0.0.1:11434
   OLLAMA_MODEL=qwen3:4b
   OLLAMA_CONTEXT_LOG_LIMIT=20
   ```

## Live test

```powershell
$headers = @{ Authorization = "Bearer $env:CHAT_API_TOKEN" }
$body = @{ question = "TOPO-A task 0 bị lỗi gì?" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8080/api/v1/chat" `
  -Headers $headers -ContentType "application/json" -Body $body
```

Expected:

- HTTP `200`.
- `sources[0].source` is `ConnectorHealingLogs`.
- `sources[0].query` equals the original question.
- `sources[0].items` are redacted persisted log rows, and `count` is their size.
- The answer cites log IDs present in `sources[0].items`; it must say no matching
  persisted log was retrieved when `count` is zero.

Direct database verification uses the same parameterized retrieval path:

```sql
EXEC dbo.spSearchConnectorHealingLogs
    @SearchText = N'TOPO-A task 0 bị lỗi gì?',
    @Limit = 20;
```
